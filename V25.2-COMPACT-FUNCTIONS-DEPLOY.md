# DEASJobs v25.2 — Compact Functions & Google indexing release

This package builds on the v25.1 Google Soft 404 mitigation. It reduces the Cloudflare Pages `functions/` directory **from 89 to 72 files**, maintaining original handlers and features.

## Why you saw more than 100 files

The uploaded v25.1 ZIP contained 89 Functions files. A larger count in GitHub is consistent with copying a new folder over an older `functions/` directory: GitHub keeps the old files unless they are explicitly deleted. Browser drag-and-drop may also hit a **100 files per upload** restriction when you upload the entire 187-file release. Simply zipping/compressing a folder does not change the route/file count after extraction.

## Recommended clean install (Windows + GitHub Desktop)

1. **Make a backup** of your current GitHub clone, or confirm your latest changes are pushed.
2. **Extract this entire ZIP into a NEW folder**, outside your GitHub clone.
3. Open Windows PowerShell in the extracted folder.
4. Run: `powershell -ExecutionPolicy Bypass -File .\INSTALL-V25.2-CLEAN.ps1 -RepoPath "C:\your\local\deasjobs-repo"` (replace with the actual clone location).
5. The installer completely **replaces** `functions/` with the 72-file version and copies updated `public/` assets. It **does not touch** `.git`, any Cloudflare D1/R2 data, or your app's live deployment.
6. Open GitHub Desktop: verify deletions of obsolete route files are staged as file changes. Commit and **Push origin** on the `main` branch. Cloudflare Pages will auto-deploy.
7. Test signup/login, swipe/apply/withdraw, employer actions, admin pilot, and public `/jobs` + `/` + `/robots.txt` + `/sitemap.xml`.
8. In Google Search Console, choose **Test live URL** for `https://deasjobs.com/` after deployment. Google indexing is not guaranteed by code changes alone.

**Do not upload these files over the old Functions folder without first deleting the old folder.** The installer avoids that failure.

## Safe API route consolidation

- 11 admin pilot route files are combined into `functions/api/admin/pilot/[[path]].js`.
- 8 application route files are combined into `functions/api/applications/[[path]].js`.
- Handler code, authorization, validations, SQL statements, status changes and notification logic are retained.
- The public API URLs do not change. Unsupported paths return HTTP 404; unsupported HTTP methods return HTTP 405.
- `functions/api/admin/pilot.js` remains separate, preserving its original top-level route.

No D1 migrations, R2 changes or secrets updates are required for this consolidation.
