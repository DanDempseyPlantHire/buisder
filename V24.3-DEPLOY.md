# Buisder v24.3 deployment

1. Back up the current GitHub repository/production branch.
2. Back up the production `buisder-db` D1 database.
3. Do not run a D1 migration for this release.
4. Extract the complete v24.3 ZIP locally.
5. Replace the repository files with the complete extracted contents, preserving `functions/`, `public/`, `workers/`, `scripts/` and all root files.
6. Commit and push to `main`.
7. In Cloudflare Pages, wait for the GitHub-triggered deployment to report Success.
8. Open `/api/health` and confirm it is healthy.
9. Hard-refresh the browser. For an installed PWA, close it completely and reopen it. If an old UI is still cached, uninstall/reinstall the PWA or clear site data/service-worker storage once.
10. Run every check in `V24.3-TEST-PLAN.md` before inviting more users.

## Important

The employer commercial-plan code remains in the repository for later reactivation, but it is not exposed to employers and it does not limit normal job posting/reopening/import in v24.3.
